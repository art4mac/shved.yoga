# Статика Astro + окремий FastAPI-бот в одному репозиторії

Лендинг збирається Astro у чистий HTML і не має жодного запиту до бекенду; бот — окремий сервіс на FastAPI + aiogram з адмінкою на starlette-admin. Обидва живуть в одному репозиторії (`site/`, `bot/`) і релізяться разом одним docker-compose за конвенціями Covent AI на інфраструктуру coventpro (Traefik + letsencrypt), тестовий хост — `shved-yoga.dev.coventpro.ai`.

## Considered Options

- **Рендер сайту на Python (FastAPI + Jinja2)** — відкинуто: тримати живий процес заради статики означає гірший TTFB без жодної вигоди.
- **Два окремі репозиторії** — відкинуто: різні цикли змін не варті синхронізації двох репо, спільний docker-compose простіший.
- **Статика на Cloudflare Pages** — відкинуто на користь власної інфраструктури, але залишено як шлях відходу.

## Consequences

У коді не має бути хардкоду хоста coventpro й абсолютних URL — перенесення статики на будь-який CDN мусить залишатися вечірньою роботою.

Адмінку вирішено тримати на тому самому домені за шляхом `/admin` (див. ADR-0005), тому Traefik обслуговує один хост двома роутерами: `/` → статика, `/admin` → FastAPI. Наслідок: домен більше не можна перевести на CDN, не забравши з нього адмінку — «статика окремо» залишається можливою лише разом із переїздом `/admin` на власний піддомен.
